### Backwards-incompatible changes

- Attempt to widen `time_t` to 64 bits during compilation and, if successful, use `libremctl.so.3` for the SONAME and `REMCTL_4.0` for the symbol versions. This is done even on platforms where no ABI change is required so that there is a consistent SONAME for libremctl with an ABI using a wider `time_t`. If the compilation platform doesn't support a wide `time_t`, use the previous `libremctl.so.1` SONAME and `REMCTL_1.0` symbol version, since the resulting library will be ABI-compatible with previous releases.
